Problem Statement & Project Motivation

  • Paper Registers & Lost Records: Traditional academies rely on physical paper sheets or WhatsApp messages that frequently get lost or miscalculated.
  • Coaching Friction: Coaches spend valuable pitch training time taking manual attendance rather than training athletes.
  • Lack of Student Transparency: Athletes and parents have zero real-time visibility into attendance percentages, membership expirations, and skill reviews.
  • The Sportivo Solution: A centralized, cloud-native web application offering three role-isolated portals for Students, Coaches, and Administrators with real-time sync.
Speaker Script (Shaik Althaf)

"Most sports clubs and coaching academies still use paper registers or scattered spreadsheets. This creates massive friction: records get misplaced and athletes have no clear picture of their attendance or skill growth. Sportivo modernizes this entire ecosystem by digitizing rosters, automating attendance percentages, and providing role-tailored dashboards."

System Architecture & Tech Stack

  • Next.js 16.3.6 (App Router): Leverages React Server Components (RSC) to render database queries on the server without shipping bulky JavaScript to the client.
  • React 19 & Tailwind CSS: Declarative client components with utility-first styling and Lucide vector iconography.
  • MongoDB Atlas & Mongoose 8.x: Highly scalable cloud document database with indexed schemas and relational referential integrity.
  • Auth.js v5 (NextAuth): Enterprise authentication featuring Google Cloud Console OAuth 2.0 and bcrypt password encryption.
  • Vercel Global Edge Network: Serverless edge deployment with automatic CI/CD git triggers and HTTPS TLS 1.3 encryption.
Speaker Script (Tanay)

"Moving to the system architecture: Sportivo is built on a serverless multi-tier architecture. We chose Next.js 16 and React 19 to take full advantage of React Server Components, keeping our initial JavaScript bundle small and fast. For our data layer, MongoDB Atlas provides managed high-availability replica sets, while Auth.js v5 handles stateless session management at the network edge."

Database Modeling & Schema Design

  • User Schema: Multi-role enumeration (student, coach, admin), unique indexed email, auto-incrementing studentId starting at 10001.
  • Enrollment Schema: Many-to-many relationship linking Student ID, assigned Coach ID, Sport discipline, and active membership dates.
  • Attendance Schema: Uses a compound unique index on { student: 1, enrollment: 1, date: 1 } ensuring an athlete cannot be marked twice on the same training day.
  • Progress Schema: Stores coach evaluations, drill performance, and skill tiers (Beginner, Intermediate, Advanced, Professional).
Speaker Script (Tanay)

"Data integrity was our top priority. In our Attendance collection, we created a compound unique index on student, enrollment, and date. This guarantees strict auditability and prevents duplicate entries. Furthermore, students receive an auto-incrementing student ID starting at 10001, making identification easy and intuitive for administrators."

Auth.js v5 & Google Cloud OAuth 2.0

  • Real Google OAuth Integration: Configured OAuth 2.0 Web Client credentials in Google Cloud Console (Project: PAS-GPT / Sportivo Web).
  • Native Browser Account Chooser: Explicitly configured prompt: "select_account" so Google prompts the user with all signed-in Gmail accounts on their device.
  • Stateless JWT Strategy: Session state is stored in cryptographically signed HTTP-only cookies, eliminating database session bloat.
  • Auto-Provisioning in signIn Callback: New Google users automatically receive a verified Student record, an allocated Student ID, and are directed straight into their student portal.
Speaker Script (Tanay)

"For authentication, we integrated live Google Cloud OAuth 2.0. By using prompt: 'select_account', the user's browser opens the native Google account selector listing their logged-in accounts. Once selected, our Auth.js callback validates the OAuth token, automatically provisions a student record in MongoDB if it's their first time, assigns their student ID, and issues a secure stateless JWT."

Presenter: Y. V. V. Tirumala Tanay

API Layer & Resilient Data Fetching

  • RESTful API Handlers: Endpoints like /api/attendance, /api/enrollments, and /api/auth/* for atomic CRUD operations.
  • Fault-Tolerant Loaders: All data queries in lib/dashboard-data.js are wrapped in try/catch blocks with safe object defaults, preventing serverless cold-start crashes.
  • Model Pre-compilation: Explicitly registered Mongoose schemas (User, Sport) to eliminate runtime MissingSchemaError during population queries.
  • Session Reset Route: /api/auth/clear cleanly deletes all chunked session tokens, allowing instant account switching.
Speaker Script (Tanay)

"Serverless edge functions can occasionally experience network latency. To make Sportivo completely fault-tolerant, every data loader implements try-catch guards with fallback states. This ensures that even during a database blip, the dashboard renders clean empty states rather than crashing into an error screen. We also added an auth-clear endpoint for reliable session resets."

Multi-Role Verification & Edge Protection

  • Edge Middleware (proxy.js): Intercepts incoming requests at Vercel's edge network before server components render.
  • Strict Portal Isolation:
    • /login & /register — Dedicated Student athlete entrance.
    • /coach — Dedicated Coach credentials entrance.
    • /admin — Master Administrator portal guarded with a 7-digit access code.
  • Smart Redirection & Escape Hatches: Prevents unauthorized cross-role access while providing ?switch=true and ?logout=true query parameters so users can switch accounts smoothly.
Speaker Script (Praneeth)

"Thank you, Althaf. I will now cover our security verification, analytics, and cloud deployment. In proxy.js, our edge middleware checks every incoming request before it hits the application server. It enforces strict role boundaries: athletes only access student routes, coaches access coach routes, and administrators require dual-factor code verification. We also engineered query escape hatches so users can switch accounts without getting stuck."
