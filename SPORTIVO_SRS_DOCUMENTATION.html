1. Introduction

1.1 Purpose

The purpose of this Software Requirements Specification (SRS) document is to provide a complete, rigorous, and verifiable technical description of the Sportivo Athletic Academy Platform. This document defines external interface requirements, system behaviors, functional rules, data flow characteristics, non-functional quality attributes, and architectural constraints.

1.2 Scope

Sportivo is a production-grade, cloud-native full-stack web application engineered using Next.js (App Router), React, Tailwind CSS, and MongoDB Atlas. It unifies sports academy operations into three role-isolated portals:

  • Student Portal: For program enrollment, certified coach discovery, schedule tracking, and skill progression analytics.
  • Coach Portal: For drill logging, collapsible athlete rosters, batch attendance submission via single-click visual green/red toggle switches, and skill assessments.
  • Master Administrator Portal: For academy governance, financial volume audits, user directories, and program allocation.

2. General Description

2.1 Product Perspective

Sportivo operates as a multi-tier, self-contained cloud platform hosted on Vercel's global edge network with MongoDB Atlas powering the persistent data tier. It interfaces with modern mobile browsers, tablets, and desktop workstations without requiring third-party runtime plugins.

2.2 Product Functions

  • Authentication & Security: Multi-provider authentication supporting Google Cloud Console OAuth 2.0 (with native browser account picker prompt) and bcrypt-hashed credential sign-in.
  • Interactive Attendance Workspace: Drill logging, roster reveal via interactive OK button dropdown, and pure green/red toggle switches.
  • Role Dashboards: Dedicated views for Students, Coaches, and Administrators with responsive analytics charts.
  • Enrollments & Memberships: Sports package catalog, coach selection, and financial transaction verification.

2.3 User Characteristics

Encompasses Student Athletes seeking self-service training visibility, Academy Coaches requiring rapid field attendance marking, and Master Administrators auditing academy records.

3. Specific Requirements

3.1 External Interface Requirements

Responsive, fluid interface utilizing glassmorphism cards, warm orange accents (#EA580C), and deep navy typography. Fully responsive across 320px mobile screens to 4K displays.

3.2 Functional Requirements

  • FR-1 (Authentication): Dedicated portals at /login (Student), /coach (Coach), and /admin (Admin). Google OAuth invokes prompt: "select_account" to list browser accounts.
  • FR-2 (Attendance System): Athlete list is collapsed by default. Clicking OK drops down the roster. Each athlete row features an accessible green (Present) or red (Absent) toggle switch.
  • FR-3 (Enrollment): Allows students to enroll in sports disciplines and binds them to coach rosters.
  • FR-4 (Progress Analytics): Computes attendance rates and milestone progress visualized through Recharts SVG components.

3.5 Non-Functional Requirements

  • Performance: First Contentful Paint < 1.2s; compound index queries execute under 50ms.
  • Reliability: Server Components include robust try/catch fallbacks so external API latency never crashes viewports.
  • Security: Encrypted JWT cookies (HTTP-only, SameSite=Lax, Secure), bcrypt 12-round password hashing, and parameterized MongoDB queries.
